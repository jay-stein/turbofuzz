# 2026-10-03 — App MVP: paste → filters → virtual table

## Goal

Turn the validated fuzzy engine into a working website: paste delimited data,
auto-detect types, and filter instantly with minimal latency.

## Decisions

- **Vanilla TS** UI (user choice): no framework, hand-rolled windowed table.
- **All queries on the main thread.** Benchmark showed fuzzy p95 0.05 ms and
  full scans ~5 ms at 100k; a worker would only add postMessage latency.
  Parsing/indexing is a one-time ~240 ms cost with a "Parsing…" state.
- **Vite** build, **Papa Parse** for quoted/newline-correct ingestion,
  comma default via delimiter sniffing (auto-detects tab/semicolon/pipe).
- Engine extracted from `bench/` to `src/search/` (single source of truth);
  `Bench` imports the same code.
- Fuzzy index is built lazily per column when Fuzzy mode is selected, so
  normal `contains` filtering never pays index-build cost.
- Query engine caches each column's bitset by signature; one changed filter
  recomputes one bitset and ANDs the cached rest. `popcount` gives the count.
- Column type inference order: boolean → identifier (leading zeros / long
  unique digit strings) → integer → number → date → category → string, with a
  per-column dropdown override that re-derives only that column.

## Verification

- `npm test`: 23 tests pass (parse, inference, filters, fuzzy).
- `npm run build`: 46.6 kB JS / 16.6 kB gzip, 6.7 kB CSS / 2.0 kB gzip.
- `npm run bench:app` at 100k rows, 5 columns:
  - parse (Papa + sniff): 71 ms
  - build (types + stats): 85 ms
  - fuzzy index build (name): 84 ms
  - combined fuzzy + contains + category + range query median: **0.06 ms**
- `npm run bench:quick` re-run confirms the engine still passes after the move.
