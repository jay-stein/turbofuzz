# 2026-10-03 — Export: copy and CSV download

## Goal

Export the current filtered/sorted result set as CSV, either to the clipboard
or as a downloaded file, without blocking the UI.

## Design

- **CSV is built in the worker** (`src/worker/csv.ts`), chunked at 20,000 rows
  per request, so a 1M-row export never builds a giant string on the main
  thread and each message stays ~1 MB.
- **Snapshot semantics**: `startExport` copies the current ordered result ids
  (`sortedIds.slice()`); subsequent `getCsv` chunks use the snapshot, so
  changing filters mid-export cannot produce a mixed file.
- Correct escaping: quotes fields containing `,`, `"`, `\n`, `\r`; doubles
  internal quotes; CRLF line endings; trailing CRLF so chunks concatenate;
  header only in the first chunk.
- **Download**: chunks collected into `Blob` parts, UTF-8 BOM prepended for
  Excel, object URL + anchor click. Filename derives from the dataset name.
- **Clipboard**: `navigator.clipboard.writeText` with a hidden-textarea
  `execCommand("copy")` fallback. Capped at 100,000 rows with a clear message
  pointing to Export CSV for the full set.
- UI: Copy and Export CSV buttons in the results bar, disabled at zero
  matches, transient status text for progress/completion.

## Measurements (bench:app, 5 columns)

| rows | CSV build | size |
|---|---|---|
| 100,000 | 67 ms | 4.7 MB |
| 1,000,000 | 584 ms | 46.7 MB |

All inside the worker; queries unaffected.
