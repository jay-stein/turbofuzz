# 2026-10-03 — Excel workbooks (.xlsx / .xls)

## Goal

Accept `.xlsx`/`.xls` in the dropzone and URL field; when a workbook has
multiple sheets, show a picker with sheet names and `rows x columns` (top 10,
biggest first, best match marked); load exactly one sheet.

## Fast path (.xlsx)

`src/parse/xlsx.ts` treats the workbook as the ZIP it is:

- Lazily imports `fflate` and unzips **only** `xl/workbook.xml`, its rels and
  `xl/worksheets/*.xml` — never shared strings or media.
- Sheet names come from `workbook.xml` + rels; sizes come from each sheet's
  `<dimension ref="A1:F100"/>` element, so no cell parsing is needed.
- If `<dimension>` is missing (some writers omit it), it falls back to
  counting `<row>` tags and peeking at the first rows' cell refs — approximate
  by design, as agreed.
- Extraction parses only the chosen sheet: shared/inline strings, booleans,
  cached formula values, and merge expansion; dates remain Excel serial
  numbers for speed.

## Legacy .xls

Handled by SheetJS, dynamically imported so its ~141 kB gzip chunk is only
downloaded by users who open a legacy file. Same picker, same one-sheet load.

## Picker

The URL table picker was generalised (`showPicker`) and reused for worksheets;
it shows the label, "best match" badge and `N rows x M columns`, capped at 10.

## Measured

- `solar.xlsx`, 11 MB, **183 sheets**: listed in **477 ms**; reading the top
  sheet 629 ms.
- Legacy `.xls`, 2.5 MB: listed in 797 ms; extracted 6,246 x 256 in 817 ms.
- Bundles: main 20.1 kB gzip; fflate chunk 3.7 kB gzip (lazy); SheetJS chunk
  141 kB gzip (lazy, .xls only).

## Known trade-offs

- The stored dimension can overstate the real data extent (formatting-only
  cells). Displayed sizes follow the stored dimension, matching the
  "fast but occasionally approximate" preference.
- Dates in `.xlsx` show as serial numbers; URL loading of workbooks works when
  the extension or content type identifies a spreadsheet.
